1. 概览

一手拿着乐器也能轻点一下记录练习时间，并在上课时展示给老师看的iPhone 应用。通过记录和分享两个界面，将日常练习带入课堂交流。

负责问题定义、UX/UI设计、真机调整、实现和资料制作。实现过程与AI协作，并由我自行判断界面和操作方案是否采用。

我在自己的练习和课程中使用了这款应用。老师表示内容一目了然，也提出了希望记录得更细致的需求（大意）。

通过 Web 演示进行操作

2. 背景与问题

我业余练习次中音萨克斯，每两周上一次课。老师问我“最近练得怎么样？”时，我却没有办法具体说明练了什么、练了多久。

萨克斯挂在背带上，练习时很难腾手在纸上写字。日记本页数一多，记录也会散落难找。

我试过时间记录应用，虽然可以一键计时，但如何把记录整理成老师一眼就能看懂的形式，仍是个问题。

3. 设计方针

让练习时的记录和上课时的分享衔接成一个完整流程。为此，我把两项要求作为决定界面和操作方式的标准。

练习时，尽量减少输入

拿着乐器也能通过轻点分类卡片记录时间。

展示给老师前，尽量减少编辑

记录能自动汇总，可以直接展示练了什么、练了多久。

4. 功能与设计

将操作和练习时间放在同一张卡片上

轻点类别卡片即可开始计时；轻点另一张卡片可切换；再次轻点同一张卡片则停止计时。卡片上醒目显示今日练习时间，只有计时过程中才会高亮并加上白色描边。操作的位置和确认记录内容的位置保持一致。

无需横向滚动即可查看练习明细

为了免去分享前的编辑，应用会自动汇总上次上课日以来的记录。每日表格优先采用能同时显示所有类别的布局，即使文字需要缩小也如此。目标是让用户能一边向老师展示画面，一边聊练习时间的分配。

让累积的练习成为坚持下去的动力

把今日完成情况以及按月、按年累积的练习可视化。我希望老师能看到自己付出的努力，这也能成为持续练习的动力。

每日｜以1小时为目标，让进度条填满

今日练习进度条最初以1小时为上限显示。我把各类别的练习时间用不同颜色叠加，希望尝试达到这个目标能成为开始练习的契机。

长期｜用绿色方格呈现日积月累

每天用一个方格表示，并以绿色深浅表示当天的练习时长。设计上希望能一览按月、按年累积的方格，并让日常记录逐渐增加的样子成为坚持练习的契机。

5. 制作过程

通过调研和交流，明确记录与分享各自的作用

我使用 ChatGPT 调研了现有应用，并梳理问题和解决方向。在当时的调研范围内，我找到了时间管理应用，但没有找到适合与老师沟通的分享机制。我通过对话逐步明确概念，整理成规格说明，再交给 Codex 读取并实现初版。

试用初版，将操作区域收进屏幕内

我亲自试用了生成的初版，提出 UI 和 UX 改进需求，并据此调整出改进版。初版中分开的计时状态信息和结束操作被整合进卡片，今日时长也改为醒目显示。我还尝试调整布局，让操作面板能完整显示在屏幕内。

练习时需要一直打开这个界面，因此以黑色为主色，同时希望类别颜色能带来明快的感觉。

亲自对比操作手感，再决定采用哪种方案

仅靠文字或图片难以准确描述“顺畅滑动、稳稳停住”的手感。因此，我与AI一起制作了一个辅助工具，可以自行更改方案和参数来测试。我以操作面板能停在屏幕范围内为标准，在真机上比较后，选择了浏览器原生的吸附滚动，并应用到程序中。

通过独立评审辅助检查，由我决定是否采用

我用两个独立的AI会话反复进行这一流程：先自行检查 Claude Code 提出的问题和改进建议，再由 Codex 验证并落实必要的修正。建议有时会偏离预期的 UI 或 UX，因此我会结合应用的目的和实际手感决定是否采用。
＊这一流程重复了约15次；当AI评审不再提出重大缺陷时，我将其作为结束改进的一个参考标准。

6. 使用结果与后续计划

练习开始时打开应用已成为习惯

我把应用安装在自己的 iPhone 上，在日常练习中使用，确认了拿着乐器也能轻点一下记录的便利性。练习开始时打开应用逐渐成为积极的习惯；回顾当天的练习顺序与分配、留意下次上课日，也有助于规划自己的练习。

老师提出希望记录得更细致

老师表示练习内容一目了然，也认为如果能记录具体音阶类型会更有帮助（大意）。这些反馈来自我自己的练习和与老师上课时的实际体验。

接下来的课题是兼顾记录细节与输入便捷

我正在考虑在“音阶”下设置“五声音阶”等子类别。如何让记录操作依然简单，还在继续探讨。对于分享界面，也在考虑用类别和子类别的层级显示取代每日表格。
