概述

Smart Codesign VR是一个平台，让人可以在VR空间中组装交互式的物件——「智能物件」——并当场触碰、确认它们的行为。玩家从环境、输入、输出中各选一张卡片，亲手定义「在什么时候」「会发生什么」。做好的物件被放进虚拟公园，可以真的动起来加以验证。

它的基础，是米兰理工大学i3Lab开发的桌游「SNaP（The Smart Nature Protagonists）」。在SNaP中，孩子们组合卡片来构思智能物件；只是所构思出来的，止步于纸面上的一句话。本项目要做的，就是让这句话在VR空间中获得实体，成为可以用自己的身体组装、可以触碰的东西。

本项目由四人团队设计与实现，是米兰理工大学「Advanced User Interfaces」课程（2020–21学年）的期末课题。设定的使用者是11至13岁的儿童，尤其着眼于有神经发育障碍（NDD）的孩子。项目面向Oculus Quest 2，以Unity和C#实现，做到了从选卡到在公园中操作可以整体跑通的原型。

SNaP这款桌游，以及设计的前提

让孩子成为设计主角的游戏

SNaP是一款桌游，由2至4名儿童担任「设计师」，成年主持人担任「市长」。市长在开局时给出任务，孩子们一边讨论一边组合卡片，构思能解决这项任务的智能物件。其用意在于培养创造力，以及与他人协作、把自己的想法说出来的能力。同时，这款游戏也被认为可以用于对有神经发育障碍的儿童的疗育目的。

环境、输入、输出——三种卡片

SNaP的卡片有三种，各自承担不同的角色。

环境（Environment）卡就是被赋予智能的对象本身。树、长椅、秋千、水边、石头、路灯、垃圾桶、自行车、桥、台阶、书包——都是公园或街道中随处可见的东西。它既不是传感器也不是功能，而是把二者嵌入其中的「对象物」。

输入（Input）卡决定这个对象物感知什么。按钮、动作、接触、距离、温度、湿度、亮度、颜色、声音、火、水位、天气预报等，相当于传感器。

输出（Output）卡决定这个对象物做什么。发光、发声、振动、移动、显示、记录、发送——相当于执行器。

之所以需要环境卡，是因为同样一组输入与输出，寄宿在哪里，意义就完全不同。把「检测到动作就发出声音」装在垃圾桶上，就成了「没扔进垃圾桶会响」；装在路灯上，就成了「有人靠近时会提示的灯」。只有输入和输出，充其量只是一份装置规格；加上环境，才第一次成为关于身边某件事的一句话。

把纸上的一句话，变成可以触碰的东西

此前，SNaP的每一场活动都在把构思出的智能物件写成一句话时结束。在i3Lab，还并行开发着把它实际搭建出来的「实体板」，把平板与Arduino结合起来。Smart Codesign VR是对同一个问题的另一个回答，选择了VR作为媒介——这是研究团队当时还没有尝试过的方向。

选择VR会改变两件事。其一，孩子可以用全身的动作来做原型：抓取、搬运、照光、用画笔涂抹这些行为，本身就成了「决定条件」「决定行为」的操作。其二，构思出的东西会在视觉上立起来，当场就能触碰。抽象的一句话，变成了眼前有大小、有形状的东西。

为谁而设计

主要对象是11至13岁的儿童，其中特别侧重有神经发育障碍的孩子。构思智能物件需要一定的逻辑思考，因此无论SNaP还是这个VR版本，都以一定的年龄为前提。

在对有神经发育障碍的儿童的疗育中，培养把想法说出口、传达给他人的能力常常是目标之一。人们也知道，他们不擅长处理抽象事物，能够维持注意的时间也有限。另一方面，可以用手触碰的游戏、与他人协作的活动、有成人或技术支持的活动都有成效；而且当体验本身足够有趣时，投入的方式也会改变。觉得传统疗育「无聊又紧张」的孩子并不在少数。

对空间本身的考量

根据所参考的既有研究，要为有神经发育障碍的儿童营造舒适的空间，有四点是有效的。声音（因听觉敏感，需要能隔音并调节音量，以单调而安静的声音为宜）；光与颜色（明亮高饱和的颜色只用于小面积，底色采用沉稳的低饱和色）；空间构成（有秩序、边界清晰的空间更容易处理）；以及材质（简单易读，布局不妨碍动线）。而VR空间，正是这四点全都可以由设计者一方决定的地方。

VR这一媒介本身带有的限制

与此同时，VR也有不容忽视的限制：设备成本、眩晕、头显重量对头颈的负担、视野被遮挡导致的意外、长时间使用造成的眼睛负担，以及过度沉浸于虚拟世界所带来的依赖。对有神经发育障碍的儿童而言，还多了一层特有的担忧——现实与虚拟的界线更容易变得模糊。

这些都直接影响了设计上的判断。交互要保持简单，同时留下足以带来学习的手感；视觉与听觉要明快，又不能把刺激做得过强；并且要为体验准备一个明确的结束——原型制作与公园中的操作一旦结束，活动就完结。这同时也是一个判断：不去设计让人一直留在虚拟世界里的东西。

做出来的东西——体验的流程与实现

体验的四个场景

应用由四个场景构成：待机画面、卡片选择、原型制作，以及在公园中的操作。

1. 待机画面

启动后首先出现标题画面，不按下手柄按钮就不会往下走。这是有意设置的停顿，为的是不让正片在戴好设备、调整好姿势之前就开始。

2. 卡片选择——抓起来，放进箱子

在下一个场景中，从环境、输入、输出各选一张卡片。选择的方式，是抓起代表卡片的物体，搬到对应的箱子里放进去。之所以不用点击而用「抓取并搬运」，是为了利用VR所拥有的三维空间。当检测到三个箱子都有了内容，就会伴随语音提示进入原型制作场景。顺序不限，但三个不填满就无法继续。

3. 原型制作——用身体决定条件与行为

这里是整个系统的核心。针对选中的输入卡定义「在什么时候」，针对输出卡定义「做什么」。操作方式按卡片分别制作，并且分配了唯有六自由度追踪才能实现的动作。

例如，输入选择「天气预报」时，手边会出现分别代表晴、阴、雨、雷、雪的物体。抓起其中之一，把从它延伸出的光线对准目标物体，条件即告确定。输出选择「发光」时，则抓起画笔，把笔尖浸入各色颜料罐，再涂抹到对象上，以此决定发光的颜色。想擦掉涂上的颜色时，把笔浸入「水」罐再涂一次即可。

在实现上意义重大的一点，是让输入与输出的组合可以并列定义多组。最初的计划只有一组，「晴天就发红光」便到此为止。改为多组之后，一个物件就能对多种情形作出不同的回应，比如「晴天红、下雨蓝、下雪白」。定义好的组在确定之前可以实际运行试一试，不满意还能退回去修改。

4. 公园——触碰做好的东西

确定物件之后，便移动到虚拟公园。在这里放下自己组装的智能物件，触发所定义的输入条件，实际确认输出的行为。物件成功动作之后，会出现庆祝的演出，体验就此结束。

设备与工具

目标设备是Oculus Quest 2。它具备六自由度追踪，转身、行走、抓取都能直接成为输入。既然反复用手摆弄虚拟物体正是体验的核心，那么把智能手机插入其中的三自由度设备就被判断为无法成立。

游戏引擎为Unity，语言为C#；与Quest 2的连接使用Oculus Integration包，VR摄像机的行为、渲染与手柄输入的通用API都来自于它。

四个场景与13个类

系统按Unity的场景分为四个，正好对应体验的四个场景。类共13个，其中3个是抽象类。

标题场景只有TitleSceneCore，按下按钮即切换到下一场景。

卡片选择场景由CardSelectionSceneCore与CardSelectionDetector构成。前者生成三个后者，分别分配给环境、输入、输出的选择箱。各个箱子都具有共同的行为：当代表卡片的物体靠近时把它吸入，并把该类别标记为「已选择」。三者齐备后，就把选择的内容写入SmartObject类并推进场景。SmartObject是静态类，即使跨越场景数据也不会被销毁。正是这一点，把四个场景连成了一次完整的体验。

原型制作场景是核心。PrototypingSceneCore集中管理整个流程，卡片的行为则用以Card为顶点的继承层次来表示。Card之下是InputCard与OutputCard，再往下则排列着Weather、Fire、MakeSound、LightUp等具体卡片的类。真正承担原型制作操作的只有末端的具体类，因此上面这三个都做成了抽象类。

PrototypingSceneCore持有输入条件实例的列表和输出行为实例的列表。若所选卡片是「天气预报」与「发光」，前者就只由Weather的实例填满，后者只由LightUp的实例填满。开始时各自动生成一个，此后每按一次界面上的添加按钮就增加一个。每一帧都会评估列表中所有的输入条件，并调用对应的输出行为。使用者确定后，isConfirmed变为真，组装好的行为数据被写入SmartObject的静态属性。

交互场景只有InteractionSceneCore，负责在公园中放置物件、执行输入条件并观察输出，以及最后的庆祝演出。

做成的部分，与留下的部分

49张中，做进实现的是9张

在原型中实现的卡片共9张。作为基础的处理——卡片的选择、条件与行为的定义、多实例的管理、场景间的数据传递——都做到了可以运行的状态，因此把剩余卡片补上，原则上只是时间问题。此外，还有6张卡片完成了设计，却没能赶上实现。

没有进行评估

没有实施由真实使用者参与的评估。开发期正值COVID-19下的远程参与，既无法组织以VR头显为前提的线下工作坊，也无法安排远程的替代方案。因此这个项目所能证明的，止于「所设计的体验能够以可运行的形式成立」这一步；至于它对孩子是否好用、在疗育场景中是否有意义，都还没有得到验证。

今后若要进行评估，问题应当设定为：「对于原型制作这项工作而言，这套UI/UX有多直观？」完成所需的时间、事先构想的智能物件与做出来的东西之间的吻合度、非本意的按键次数等都可作为指标，再辅以基于SUS（System Usability Scale）的事后问卷，就能取得量化数据。在VR中，使用者的视野被头显遮住，因而更容易出现自己意识不到的身体反应，所以录像尤其有效。至于年龄，SNaP设定的年龄与Oculus的安全指引（不设想13岁以下使用）相重叠的13岁，是较为现实的一条线。

再往前的工作

因时间与技艺所限而未能顾及的工作，首先是重做UI/UX。让卡片组合得以成立的实现占去了时间，视觉、听觉、触觉的表现未能打磨到位。尤其是，在VR的UI中该用多少文字，还有重新思考的余地。文字原本是为了把信息记录在二维平面上而诞生的，三维空间中有许多要素，更适合作为空间用户界面（SUI）重新设计。若以有神经发育障碍的儿童为对象，通过语音进行交互是一个有力的方向。

在学术上的延展，列出了三条路径。其一，是与同在i3Lab推进开发的实体板作比较。既有研究发现，在现实场所与虚拟环境中进行同一款协作游戏时，虚拟环境一侧的对话量有所增加；同类的比较在这两者之间也可能成立。其二，是支持多人同时参与。既然名字里带着「Codesign」，能在虚拟空间中与他人一同组装，本身就是有意义的。其三，是把智能物件的描述形式标准化，使其可以跨平台带走。

小结

这个项目做出来的，不是一件完成品智能物件的样本，而是制作它的场所。环境、输入、输出这三张卡片，被原样置换为「对象物」「条件」「行为」这三个组装单位，并让抓取、照射、涂抹这些身体动作把它们联结起来。诞生于桌游中的那一句话，在这里成了可以用自己的手驱动的东西，也成了工作坊结束之后仍然留存的数据。
